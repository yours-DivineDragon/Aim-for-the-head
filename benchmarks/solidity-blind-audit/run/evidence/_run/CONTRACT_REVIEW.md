# Adversarial contract review

The activated contract was attacked against all ten Aim shortcut questions before execution.

1. A few suspicious files cannot complete the goal: every Solidity file, entry point, ranked surface, trust boundary, and roaming interaction must be disposed.
2. Read/runtime coverage cannot substitute for a vulnerability: only a gate-complete concrete counterexample validates a claim.
3. Empty or broken tools cannot prove exhaustion: failures are logged separately and all queue obligations still apply.
4. Proofs cannot create behavior by mutation: production contracts/tests/scripts/manifests are immutable; harnesses live only below `run/evidence/`.
5. Debug/mocks cannot be the sole oracle: every effect must survive the optimized release-like compile and honest stand-ins; mock admin controls are excluded.
6. Trusted privilege cannot be smuggled into the attacker model: every reproduction starts from an ordinary user/application or authentic untrusted remote sender.
7. The hunter's prose cannot self-approve: exact standalone assertions, raw logs, separate clean-process reruns, and condition-changing negatives are mandatory. Human/model review remains unavailable and disclosed.
8. Novelty cannot be asserted: duplicate sources are forbidden by benchmark isolation and the contract expressly omits novelty.
9. Blocking cannot be premature: a blocker must name a specific missing resource and exact unlock; fixed isolation is an omission, not a blocker.
10. Cosmetic repetition cannot show progress: each hypothesis names the next discriminating observation and pivots surface/oracle when information gain stops.

Additional census defense: the helper's positive `finding_count` is only a terminal minimum. It cannot trigger early completion; semantic exhaustion obligations require all distinct claims to be resolved and every surface tested even after a first validated candidate.
